> **Modo TDD estricto.** Dentro de cada grupo se escribe primero la prueba que falla, después el código mínimo que la pasa, después se triangula con un segundo caso (al menos camino feliz + un borde) y recién entonces se refactoriza, con las pruebas en verde después de cada paso. Antes de tocar un archivo que ya existe se corre su suite y se anota la línea base; una falla previa se reporta, no se arregla.
>
> **Gobernanza.** Este change es de dominio CRÍTICO (autenticación, autorización, auditoría). Ninguna tarea se implementa sin la aprobación humana explícita de esta proposal (`CLAUDE.md` §6, paso 4). Las tareas marcadas **[ALTA]** tocan configuración de despliegue: se describe el cambio y se espera confirmación antes de escribirlo. Las tareas marcadas **[BLOQUEADA]** no se ejecutan hasta que exista el ADR correspondiente.
>
> Orden de los grupos: roles de base → esquema → catálogo → dominio → repositorios → servicios → seguridad → endpoints → aislamiento → frontend → verificación.
