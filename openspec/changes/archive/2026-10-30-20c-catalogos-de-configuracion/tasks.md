# Tareas — 20c-catalogos-de-configuracion

> Modo TDD estricto: en cada tarea de los grupos 1 a 11, la prueba que falla se escribe **antes** que el código (RED → GREEN → TRIANGULATE con al menos dos casos por comportamiento → REFACTOR, con la suite en verde después de cada paso). Antes de tocar un archivo existente se corre su suite como **red de seguridad** y se anota la línea base; una falla previa se informa y no se arregla de paso. Ninguna aserción trivial. Las tareas están escritas con la opción **recomendada** de cada decisión de `design.md`; si el usuario elige otra en 0.1, se actualizan antes del apply (`openspec-update-change`).
>
> **Dónde va el código:** motivos y alícuotas en `backend/app/modules/configuracion/` (`domain/valores.py`, `commands.py`, `service.py`, `repository.py`, `queries.py`, `schemas.py`, `api.py`); el verificador de uso de alícuotas lo registra `catalogo` (D9); el redondeo por defecto en `identidad/` (`domain/valores.py`, `commands.py`, `service.py`, `api.py`, `router_parametros`). Frontend: `frontend/src/areas/admin/configuracion/` (tres pestañas), `features/configuracion/`, `domain/configuracion/` (nombres de ámbitos, porcentaje ↔ fracción), `areas/admin/precios/ListaFormScreen.tsx`, `ayuda/textos.ts`. Contratos de `lint-imports` sin cambios (`configuracion` no importa `catalogo`).
>
> **Lotes de apply (`design.md` D0):** Lote 1 = grupos 1 a 3 (migración y motivos). Lote 2 = grupos 4 a 6 (alícuotas y redondeo por defecto). Lote 3 = grupos 7 a 14 (pantallas, ADR, ayuda, concurrencia, cobertura, docs y prueba manual). **No se frena entre lotes**: el resumen de cada lote informa las comprobaciones automáticas y el usuario revisa con todo el change implementado.
>
> **Gobernanza BAJA** (`04` §9): sin puntos de control críticos; solo la aprobación inicial (0.1, 0.2). Cualquier ampliación de alcance durante el apply se detiene y se consulta.
>
> **Pruebas:** en cada lote solo las afectadas; las suites completas una sola vez, en 12.1. `pytest` por carpeta con `backend/.venv`; frontend con Docker detenido. **Sin fixtures compartidos** (no cambia ninguna regla de cálculo; el redondeo por defecto no participa del cálculo del precio). Si durante el apply aparece un cálculo compartido entre Python y TypeScript, se detiene y se agrega el fixture antes del código.
